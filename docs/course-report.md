# Java 局域网聊天课程报告与演示

## 项目目的与完成范围

项目用 Java Socket/ServerSocket 与 Swing 实现一个可信局域网聊天室。MVP 已完成单服务端多连接、用户登录、群聊、指定用户私聊、在线用户管理、协议/输入校验和可检测断线后的清理与手动重连。构建产物为一个含依赖 JAR，以不同入口分别启动服务端和客户端。

2026-10-27 增加 X1 双向心跳与可配置失联检测，X2～X6 未实现。账号密码、数据库、多聊天室、文件传输、音视频、公网部署不属于本次实现。用户已反馈完成心跳加入前的宿主机＋虚拟机跨系统人工验收，基本功能正常；双物理设备未测，未将虚拟机测试写成两台物理设备测试。

## 核心技术与关键流程

服务端接受线程为每个连接分配一个有名额限制的读取任务。ConcurrentHashMap 保存用户到会话的映射；短注册锁使名称预留、就绪变更、列表版本与快照保持一致。同一连接所有输出受写锁保护，网络发送发生在注册锁之外。AtomicBoolean 与条件移除保证重复清理不误删同名新连接。

协议采用 LF 分隔的 UTF-8 JSON，现成 Gson 库负责转义。读取时限制 16 KiB，避免无换行输入无限占用内存；服务端校验 2000 Java char 正文边界。身份和时间均取自服务端；伪造请求中的 from 不影响最终身份。

群聊经过“读取 → 校验 → 会话身份 → 生成事件 → 所有就绪会话逐个写入”，发送者也只显示返回的一份事件。私聊经过“读取 → 校验目标 → 定位目标会话 → 先写目标 → 成功后回显发送者”，不会经过公共广播；第三方 Socket 未收到私聊是隔离验收依据。

Swing 的连接、读取和写入都在后台；事件通过 EDT 更新组件。每次连接拥有独立对象，回调执行时核对当前对象，防止旧连接异常和旧 EDT 事件影响重连。在线列表版本在重连时重置。私聊对象消失后明确禁止继续发送，避免把保留的私聊草稿变成群聊。

详细材料：[设计说明](design.md)、[协议](protocol.md)、[需求](requirements.md)。

心跳在登录后由两端独立发送 PING，只接受同连接、同编号的 PONG 完成本轮探测；默认间隔 10 秒、响应期限 20 秒。网络写入与超时检测分开运行，普通聊天空闲不会被当作断线。超时关闭 Socket、服务端释放名称并推在线列表，客户端提示手动重连；不增加自动重发或送达确认。

## 验证结论

Windows/JDK 25.0.4 环境以 Java 17 目标编译，初始 MVP 为 28 项、分栏 UI 为 35 项测试通过；2026-10-25 增加纯色/渐变背景、自选颜色、暗色模式与统一下拉菜单后，完整构建 **46 项测试全部通过，0 跳过**。原有三方群聊/私聊隔离、并发、边界、异常清理与手动重连回归均保留；新增外观偏好保存、无效配置回退、保存失败提示，以及切换外观不丢失草稿或连接的检查。使用 computer-use 在真实 Windows 窗口验证了菜单、模式切换、自选色值应用和深色下正常发送。仅外观偏好保存在本机，聊天历史仍不持久化；网络接口和数据协议不变，组件结构见 [UI 设计与扩展说明](ui-design.md)。

2026-10-27 心跳扩展后的完整构建 **54 项全部通过，0 失败/错误/跳过**；新增本机单向丢包代理、错误 PONG、不完整响应、空闲保活、名额回收、旧连接隔离及线程释放测试。该阶段未重做虚拟机断网；2026-10-28 用户补充已测试，虚拟机断网一段时间后可自动检测断开、功能正常。实际测试日期、配置和精确耗时未提供，不将本机代理与用户实测互相替代，也不推定硬实时期限达标。

初始 MVP 的 10 个测试客户端运行 **600.49 秒**、600 轮，完成 6000 次群聊投递与 1200 次私聊投递，最长本机单轮收发耗时 9 ms，停止后服务端相关线程回到 0。内存观测包含测试探针和未 GC 对象，不将堆增量等同于服务端泄漏，也不宣称生产级性能。

心跳加入前的人工验收由用户执行：宿主机运行服务端和 alice，虚拟机运行 bob、carol，原待人工项目已执行，基本功能正常。虚拟机断网后 bob 发消息，不到一分钟显示中断；空闲 carol 保持旧状态，恢复网络后仍需手动断开再连接，或发送后等待中断再重连。这是旧版无心跳时的历史观察，不是新版本检测耗时，也不将其视为固定超时保证。

人工记录来源为用户文字反馈，未附截图/收包日志、虚拟化网络模式、双方 IP 或虚拟机运行环境；双物理设备、其他系统及 JDK 17 运行时没有独立实测记录。完整过程见 [测试报告](test-report.md)。

## 五分钟演示脚本

| 时间 | 操作 | 应看到的证据 |
| --- | --- | --- |
| 0:00～0:40 | `java -jar target/ltalk-1.0.0.jar`；启动 alice、bob、carol 三客户端并连接 | 监听地址与端口；三端列表一致 |
| 0:40～1:20 | alice 群聊 G-001；bob 回复中文、emoji、换行 | 三端都有每条事件，发送者不重复 |
| 1:20～2:10 | alice 选择 bob，发 P-001；bob 私聊回复 | 仅 A/B 收到；C 实际网络收包无 PRIVATE_MESSAGE，可同时展示对应集成测试 |
| 2:10～2:50 | 再开客户端用 alice 登录；alice 尝试空白和超长正文 | 重名新连接报错，原 alice 保持；错误请求不广播 |
| 2:50～3:30 | alice 选择 bob 并保留草稿，bob 断开 | 列表移除 bob、目标标签要求重选、草稿保留、不能自动发到群聊 |
| 3:30～4:10 | bob 重新连接；alice 明确重新选 bob 或群聊 | 成功加入，目标变更清楚可见 |
| 4:10～5:00 | 关闭服务端，然后重新启动，客户端手动连接 | 断线提示、禁用发送、可重连；无断线期间消息补发 |

跨系统演示可按已验证的分布运行：宿主机服务端＋alice、虚拟机 bob＋carol，填写宿主机对应网卡的 IP，记录虚拟化网络模式与测试证据；这与全部客户端连接回环地址不同，也不等同于双物理设备测试。

## 后续改进

心跳已实现并通过本机自动化，用户也反馈虚拟机断网检测正常；可按课程取证需要补配置/耗时及恢复重连记录。若需抵抗慢客户端，再增加有界业务输出队列与淘汰策略；认证、TLS、历史与离线消息应独立设计。阶段决策、实际问题及验证演变见 [开发日志](DEVLOG.md)，不在现有基础上直接宣称安全认证或可靠投递。
