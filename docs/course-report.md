# Java 局域网聊天课程报告与演示

## 项目目的与完成范围

项目用 Java Socket/ServerSocket 与 Swing 实现一个可信局域网聊天室。MVP 已完成单服务端多连接、用户登录、群聊、指定用户私聊、在线用户管理、协议/输入校验和可检测断线后的清理与手动重连。构建产物为一个含依赖 JAR，以不同入口分别启动服务端和客户端。

没有增加 X1～X6 扩展。账号密码、数据库、多聊天室、文件传输、音视频、公网部署不属于本次实现。两个真实设备的局域网验收尚未具备条件，当前不能宣称所有 P0 最终验收完成。

## 核心技术与关键流程

服务端接受线程为每个连接分配一个有名额限制的读取任务。ConcurrentHashMap 保存用户到会话的映射；短注册锁使名称预留、就绪变更、列表版本与快照保持一致。同一连接所有输出受写锁保护，网络发送发生在注册锁之外。AtomicBoolean 与条件移除保证重复清理不误删同名新连接。

协议采用 LF 分隔的 UTF-8 JSON，现成 Gson 库负责转义。读取时限制 16 KiB，避免无换行输入无限占用内存；服务端校验 2000 Java char 正文边界。身份和时间均取自服务端；伪造请求中的 from 不影响最终身份。

群聊经过“读取 → 校验 → 会话身份 → 生成事件 → 所有就绪会话逐个写入”，发送者也只显示返回的一份事件。私聊经过“读取 → 校验目标 → 定位目标会话 → 先写目标 → 成功后回显发送者”，不会经过公共广播；第三方 Socket 未收到私聊是隔离验收依据。

Swing 的连接、读取和写入都在后台；事件通过 EDT 更新组件。每次连接拥有独立对象，回调执行时核对当前对象，防止旧连接异常和旧 EDT 事件影响重连。在线列表版本在重连时重置。私聊对象消失后明确禁止继续发送，避免把保留的私聊草稿变成群聊。

详细材料：[设计说明](design.md)、[协议](protocol.md)、[需求](requirements.md)。

## 验证结论

Windows/JDK 25.0.4 环境以 Java 17 目标编译，最终完整构建 **28 项测试全部通过，0 跳过**。真实本机 TCP 集成覆盖三方群聊/私聊隔离、并发登录与发送、输入和帧边界、异常清理与手动重连。Swing 组件层验证连接状态、私聊目标失效、草稿保留、群聊切换和消息唯一回显。

10 个测试客户端运行 **600.49 秒**、600 轮，完成 6000 次群聊投递与 1200 次私聊投递，最长本机单轮收发耗时 9 ms，停止后服务端相关线程回到 0。内存观测包含测试探针和未 GC 对象，不将堆增量等同于服务端泄漏，也不宣称生产级性能。

人工 GUI 操作、多设备局域网、拔线现象、其他操作系统及 JDK 17 运行时均保留为未验证。完整记录与补测表见 [测试报告](test-report.md)。

## 五分钟演示脚本

| 时间 | 操作 | 应看到的证据 |
| --- | --- | --- |
| 0:00～0:40 | `java -jar target/ltalk-1.0.0.jar`；启动 alice、bob、carol 三客户端并连接 | 监听地址与端口；三端列表一致 |
| 0:40～1:20 | alice 群聊 G-001；bob 回复中文、emoji、换行 | 三端都有每条事件，发送者不重复 |
| 1:20～2:10 | alice 选择 bob，发 P-001；bob 私聊回复 | 仅 A/B 收到；C 实际网络收包无 PRIVATE_MESSAGE，可同时展示对应集成测试 |
| 2:10～2:50 | 再开客户端用 alice 登录；alice 尝试空白和超长正文 | 重名新连接报错，原 alice 保持；错误请求不广播 |
| 2:50～3:30 | alice 选择 bob 并保留草稿，bob 断开 | 列表移除 bob、目标标签要求重选、草稿保留、不能自动发到群聊 |
| 3:30～4:10 | bob 重新连接；alice 明确重新选 bob 或群聊 | 成功加入，目标变更清楚可见 |
| 4:10～5:00 | 关闭服务端，然后重新启动，客户端手动连接 | 断线提示、禁用发送、可重连；无断线期间消息补发 |

多机演示时至少将 bob/carol 中一端放到第二台设备，填服务端实际局域网 IPv4，按测试报告补记设备、网络和证据；不要拿全本机演示替代局域网实测。

## 后续改进

若课程要求发现静默断网，先实现独立 PING/PONG 心跳并区分聊天空闲；若需要抵抗慢客户端，增加每会话有界输出队列与淘汰策略。账号认证、TLS、历史与离线消息应独立设计，不在 MVP 基础上直接宣称安全认证或可靠投递。
