# Java 局域网聊天课程报告与演示

## 项目目的与完成范围

项目用 Java Socket/ServerSocket 与 Swing 实现单机聊天服务和桌面客户端。支持可信局域网及可选公网 TLS 模式。构建产物为一个含依赖 JAR，以不同入口分别启动服务端和客户端。

当前演示以 `8bc1f94` 为功能基线。课程扩展 X1～X6 已实现，包括心跳、导出、账号认证、历史持久化、好友离线留言及图片和文件传输。桌面还支持独立群组、会话分类、信息卡片、按需浏览与搜索历史、未读定位、引用回复和 60 秒撤回。[当前状态](STATUS.md)

## 核心技术与关键流程

服务端为每个获准的连接分配读取任务。会话注册表同步处理名称预留、就绪变更和在线列表版本与快照。每连接的有界 FIFO 由独立写线程输出。AtomicBoolean 与条件移除共同保护连接清理。

协议采用 LF 分隔的 UTF-8 JSON，Gson 负责转义。普通帧上限为 16 KiB，指定头像相关帧上限为 176 KiB，正文最多 2000 个 UTF-16 单元。身份与消息时间取自服务端。演示的客户端和服务端都使用协议 v7。

群聊先校验身份与会话并归档，再向就绪接收者投递。公共消息覆盖所有就绪账号，独立群消息只发给当前群成员。私聊先校验好友关系或在线私聊许可并归档，在线目标入队后回显，离线好友下次通过历史查阅。集成测试用第三方 Socket 核对投递范围。

服务端将账号、好友、群组、聊天历史和附件元数据保存到 `ltalk.db`。每条私聊正文只存一份，同一事务写入双方的可见记录。原始附件保存在服务端的 `attachments/` 目录。

连接、读取和发送都在后台执行，Swing 组件在 EDT 更新。每次连接拥有独立对象，回调执行时核对当前对象。在线列表版本在重连时重置。草稿与历史按会话保存，历史与实时事件以服务端消息 ID 合并。

详细材料：[设计说明](design.md)、[协议](protocol.md)、[需求](requirements.md)。

心跳在 HELLO 或直接登录成功后由两端独立发送 PING，只接受同连接、同编号的 PONG 完成本轮探测；默认间隔 10 秒、响应期限 20 秒。网络写入与超时检测分开运行，普通聊天空闲不会被当作断线。超时关闭 Socket、服务端释放名称并推在线列表，客户端提示手动重连；不增加自动重发或送达确认。

## 五分钟演示脚本

在项目根目录构建后，用以下命令启动独立的演示数据库。预注册 alice、bob、carol 三个账号，分别打开客户端连接同一服务端。演示重启时重复同一条命令。

```powershell
java "-Dltalk.dataDir=target/demo-data" -jar target/ltalk-1.0.0.jar
```

| 时间 | 操作 | 应看到的证据 |
| --- | --- | --- |
| 0:00～0:40 | 按 README 启动服务端，三个客户端分别连接并登录，点击公共聊天室标题 | 监听地址与端口，群聊卡片显示三个在线成员 |
| 0:40～1:20 | alice 群聊 G-001；bob 回复中文、emoji、换行 | 三端都有每条事件，发送者不重复 |
| 1:20～2:10 | alice 点击 bob 的群聊头像并从用户卡片打开私聊，提交申请。bob 从左侧加号菜单进入「通知」并接受。alice 发 P-001，bob 引用回复 | 仅双方收到，点击引用定位 P-001。输入框右上方箭头返回最新消息。第三方 Socket 的隔离证据见集成测试 |
| 2:10～2:50 | 再开客户端用 alice 登录；alice 尝试空白和超长正文 | 重名新连接报错，原 alice 保持；错误请求不广播 |
| 2:50～3:30 | alice 选择 bob 并保留草稿，bob 断开 | 在线人数减少，已获私聊许可的离线非好友会话可读历史，草稿保留。离开会话后可从「列表外的会话」重新打开 |
| 3:30～4:10 | bob 重新连接并登录，alice 在「公共聊天室」分类重选 bob，从私聊更多菜单导出 JSON | 本人私聊历史恢复，导出文件只含 alice 与 bob 的记录 |

额外演示可让两端确认好友关系并给离线好友留言，或创建需审核的独立群。加入后从群聊卡片复制 10 位群号，用「转让管理员」搜索并选择接任者。退出后从「列表外的会话」查看已授权记录。可分别发送图片和文件，再对其中一条在 60 秒内撤回，核对对端原位置的提示。离开会话并收到几条实时消息后重新打开，可演示首条未读定位。

跨系统演示可按已验证的分布运行：宿主机服务端＋alice、虚拟机 bob＋carol，填写宿主机对应网卡的 IP，记录虚拟化网络模式与测试证据；这与全部客户端连接回环地址不同，也不等同于双物理设备测试。
