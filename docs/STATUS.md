## 已确定的方案与用户偏好

- **技术与规模**：Java 17 兼容 API、Maven 单工程、Swing/Java2D、阻塞 TCP，减少课程项目依赖，面向 5～10 个正常客户端；当前不迁移 Web UI 或引入数据库。
- **协议**：UTF-8、LF 分隔 JSON，Gson 2.11.0；16 KiB 帧、2000 Java UTF-16 char 正文；userId 为 1～20 位字母/数字/下划线。默认端口 9000、监听 0.0.0.0、最多 20 个连接（含未登录），登录绝对期限 10 秒。服务端绑定身份与时间，LOGIN_OK 先于业务事件，私聊不走广播。
- **线程与交付语义**：网络在后台，展示在 EDT；提交发送队列后清空输入，正式消息仅来自服务端回显；回显不代表已读，也无幂等重试。保留旧连接隔离、列表 revision 与私聊目标离线保护，避免重连或目标变化导致误发。
- **可扩展性**：网络/路由与展示状态/组件分开。未来联系人元数据按稳定 userId 关联；GROUP.key 可扩展，但当前协议无 groupId，多群必须先设计后端/协议，不能只新增假会话入口。
- **界面偏好**：采用项目自己的中性命名，代码、报告、素材名和 Git 提交不标注模仿外部聊天产品。保持简洁分栏、蓝色强调、圆角、清楚的消息层级和协调菜单；背景仅纯色/渐变、允许自选色，支持深色和窄屏。后续仍会调整前端，应保留组件扩展点。
- **外观存储**：`${user.home}/.ltalk/appearance.properties`，仅保存外观。浅深色独立色对、共用背景类型；坏配置回退默认不覆盖原文件，原子保存失败提示并保留当前外观/草稿；不保存聊天/地址/身份。
- 用户允许继续使用 computer-use；需要权限时告知。此前授权超时不是禁止使用。

## 已知问题、限制与复现

1. **静默断网仍未修复（用户实测 + 代码确认）**：宿主机运行服务端和 alice，虚拟机运行 bob/carol；断开虚拟机网络，bob 发消息后不到一分钟显示中断；carol 不操作则保留旧界面，恢复网络后也未主动恢复。操作“断开 → 连接”可恢复。`ChatClient.receive` 登录后 `setSoTimeout(0)`，无 PING/PONG；检测耗时不是固定保证，不能用聊天空闲超时代替心跳。本次不重新复现，详情见测试报告 Q17。
2. **慢连接与历史规模（代码边界，未做专项压力验证）**：服务端同步逐连接写；客户端若停止读取可能拖慢广播。Store 历史随进程累积，时间线未虚拟化；`MessageTimeline.showEntries` 每次渲染滚到底部，未实现阅读旧消息时保持位置。可在后续专项测试中使用不读 Socket 的客户端、大量记录与停留历史位置收新消息检查；当前不能据此声称所有规模均稳定。
3. **外观窗口小屏风险（代码观察，尚未原生验收）**：AppearancePanel 首选 460×572、对话框不可缩放；主窗口窄屏通过不代表设置窗口在小屏/高 DPI 下完整可见。后续在可用区域小于设置窗口时检查全部字段和应用/取消是否可达。
4. **构建警告**：本次离线重复 package 成功，但有 JDK 25 工具链 native-access/Unsafe 及 Shade 重叠类/资源警告；日志保留，未在此文档阶段调整依赖或打包配置。

此外，无身份认证/TLS、无持久化聊天/离线消息/自动补发，客户端应运行于可信课程局域网。私聊对方离线后保留当前页/草稿并禁发，重新上线仍需明确重选，这是已验证的保护行为。
