## 状态与设计约定

- 保持 Java 17 release、Swing/Java2D、阻塞 TCP、Gson/JUnit；网络、密码计算、头像文件处理、导出在后台，展示与会话状态在 EDT；JNA 仅用于 Windows 本地文件对话框，不参与协议/服务端路由。
- ChatClient 状态为 DISCONNECTED → CONNECTING → SERVER_CONNECTED → AUTHENTICATING → CONNECTED；错密码回 SERVER_CONNECTED；故障回 DISCONNECTED，需手动连接。旧直接 connect 登录 API 保留。
- 用户明确退出登录：关闭认证 Socket，清空展示身份、历史/草稿与密码，保留用户名，随后新建未认证连接。切换账号：ClientSessions 保留当前会话并新建候选，成功才交接和清理旧数据；返回聊天关闭候选、清凭据、恢复旧地址，旧账号自身断线时不显示返回失效聊天入口。不自动恢复账号身份。普通故障重连仍保留同用户名的本窗口历史/草稿；成功换身份清除前身份数据。
- 私聊对象离线保留会话/草稿并禁发，重新上线必须明确重选。发送入队/归档/回显不等于已读或可靠送达，不自动重发。
- 协议 **v4**：新增 HISTORY_REQUEST/PAGE/END、HISTORY_DELETE/DELETED，保留 HELLO、PROFILE_GET/UPDATE/OK，LOGIN_OK 带本人资料；客户端/服务端一起升级，无版本协商。UTF-8/LF JSON、16 KiB 帧、2000 UTF-16 char 正文；用户名 strip 后 1～20 ASCII 字母/数字/下划线且区分大小写，昵称 strip 后 1～40 char，密码 6～128 char 不 strip。
- 默认端口 9000、监听 0.0.0.0、20 个连接（含未认证）。接受后 10 秒内须 HELLO 或直接登录；握手后心跳保活。客户端连接/认证响应默认 3/5 秒。
- 心跳默认间隔 10000 ms、响应期限 20000 ms，JVM 属性 `ltalk.heartbeat.intervalMillis` / `ltalk.heartbeat.timeoutMillis`；仅匹配 PONG 完成本轮，约间隔＋期限＋调度容差，无硬实时保证。
- PBKDF2-HMAC-SHA256 600000 次、16 字节随机盐、256 位输出；身份绑定当前 TCP，无独立 token。CLI 默认工作目录 data，可 `-Dltalk.dataDir` 固定；程序化服务器默认临时目录，可 start 前设置 dataDirectory(Path)。
- 稳定用户名用 UTF-8 十六进制作为文件键；服务端单目录独占锁，资料先原子发布再更新内存。归档先于投递、跨账号文件非事务；每连接历史/导出各一个固定末尾/范围快照、每页一条，客户端消费后翻页/流式导出。
- 中性项目命名、蓝色强调/圆角/协调菜单，无背景纹样；外观仅保存 `${user.home}/.ltalk/appearance.properties`，不存地址、身份、密码或聊天。会话状态、组件与网络路由保持分离。

## 已知限制与按需下一步

- 同步广播/归档可能等待慢端；聊天投递与删除为保证先后顺序串行执行，删除也可能等待慢端，归档跨文件非事务；本轮资料原子保存失败检查不能代替整个归档磁盘故障恢复专项。
- ConversationStore 历史仍随进程累积，时间线显示仍滚到底；未改容量/阅读位置策略。
- 资料响应超时可能已在服务端保存，客户端提示结果未确认，须重登核对；头像昵称只展示本人，联系人仍显示用户名。
- 明文 TCP、无 TLS/限流/找回密码；加盐存储不代表传输加密。握手未认证连接也会占名额，应关闭不使用的客户端。
- 数据目录相对启动目录，长期使用应固定绝对路径；不删除真实账号/锁文件绕过问题。离线 clean 插件未缓存的旧限制及 JDK 25 native-access/Unsafe、Shade 警告保留。
- 下一步仅按用户选择：新版启动/头像/会话导出的人工与多机验收；高 DPI 与小屏文件选择/外观窗口；慢端/存储专项；联系人元数据/多群需独立协议设计，历史容量/按时间查询按需选定。不自动实施这些建议。
