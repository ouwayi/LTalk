# LTalk 后续开发路线图

整理于 **2026-11-16（Asia/Shanghai）**。本页记录已讨论的开发方向、建议和待定取舍。当前功能、协议和验证以 [STATUS](STATUS.md)、[通信协议](protocol.md) 和 [测试报告](test-report.md) 为准。

## 1. 单机云部署、公网连接与约 100 人在线

- **部署形态**。同一个 Swing 客户端可连接局域网服务器，也可通过域名或 IP 连接云服务器。单台服务器可以通过一个 TCP 监听端口接入多个客户端，默认端口为 `9000`。各自部署的服务端各自管理账号和历史。若局域网用户和远程用户需要同一份数据，可让双方连接同一台服务端。
- **跨网试用**。先在单台云主机上通过 VPN 或私有组网验证登录、群聊、私聊、心跳和断线恢复，限制聊天端口仅在私网可达。部署时固定数据目录，验证备份恢复，并记录连接数、错误和资源占用。
- **直接开放公网**。在连接层加入 TLS，客户端验证证书和所填的主机名后再发送认证数据，握手或验证失败时明确提示。限制未认证连接、连接与握手时间、登录和注册请求频率。聊天帧与应用握手可继续沿用，配套补充部署说明和跨网验证。
- **约 100 人在线**。当前默认最多 20 条连接，含未认证连接，常规负载回归覆盖 10 个本机客户端的短时收发。服务端先做按连接的有界发送队列，保持同一连接上的必要消息顺序，限制慢客户端积压对其他人的影响。为 100 个已登录账号留出登录和重连余量，用真实 TCP 客户端验证长时在线、集中登录和重连、群聊突发及慢读客户端。记录消息延迟、断线率、线程、CPU、内存和归档开销。
- **容量取舍**。在线人数和同时发言、加载历史的人数分别影响负载。例如 100 个账号都能收到公共群消息时，每秒 5 条群消息对应约 500 次实时投递和 5 次共享归档追加。先为单机目标测量，再决定是否优化存储、线程模型或扩展到多实例。100 人为待验收目标。

## 2. 启动与局域网自动发现

- 为 Windows 用户提供双击启动客户端的入口，减少首次使用时运行 `java -cp ...` 的步骤。
- 启动时可在后台发出 LTalk UDP 广播发现请求，启用发现的局域网服务端返回名称和聊天 TCP 端口。建议首版约 2 秒收集候选，再交给原有 TCP `HELLO / HELLO_OK` 流程。自动连接完成后由用户登录。
- 发现一台就尝试连接，多台时显示名称和地址供选择，未找到或连接失败时留在原连接页。手动连接随时可用，显式指定的启动地址优先。可以保存最近使用的服务器地址，方便再次连接局域网或云端服务器。
- 服务端提供发现开关，云部署可关闭。验收单台、多台、无响应和取消发现，并在真实设备上核对防火墙、访客网络隔离和不同子网下的手动回退。

## 3. 好友、陌生人私聊与群组

- **好友首版**。按稳定用户名发申请，接收方可接受或拒绝，双方确认后由服务端保存关系。好友列表显示在线和离线状态，方便跨设备登录后继续找人。好友离线时可查看已有历史，发送等待对方上线。允许解除好友关系，双方各自保留已有聊天历史。
- **陌生人私聊**。熟人局域网可继续从在线列表直接发起临时私聊。如果未来允许陌生人注册，可先提供一条私聊请求，接收方可接受、拒绝或屏蔽。接受私聊与同意加好友分别确认，私聊许可由服务端执行。
- **群组**。当前版本有一个公共聊天室。后续考虑多个独立群组，具体的创建、邀请或申请、加入、退出及成员管理规则待定。设计时按群区分消息路由和历史授权，并明确入群前和退群后各自可见的范围。

## 4. 表情包、图片与文件

- **建议顺序**。先做 Emoji 选择面板和内置表情包，再做限大小、限像素的静态图片，最后扩展到普通文件。Emoji 沿用文字格式。内置表情包随客户端分发，聊天与历史通过表情 ID 展示。自定义表情包可以复用图片上传。
- **图片体验**。选择图片、校验文件和像素、显示缩略图、按需打开原图。可以复用头像导入的读取和校验逻辑。普通聊天帧上限为 16 KiB，头像的大帧额度适用于指定帧类型。
- **附件传输**。聊天帧携带附件 ID、名称和大小，文件内容走独立传输连接，上传成功后再发布附件消息。下载在服务端核对账号及会话权限。群聊中用文件卡片按需下载。普通文件补充进度、取消、断线后的临时文件清理、大小限制、磁盘配额和安全文件名处理。
- **历史与保留**。决定图片或附件能在历史里打开多久，以及过期后如何提示。一方删除本人记录后，另一方在保留期内仍应能访问自己的附件。图片阶段先验证这些规则，再让普通文件沿用。

## 5. 存储与数据库

- 单机小规模试用可以继续沿用文件存储。若长期积累真实聊天记录，或压测发现归档延迟、会话查询和整文件重写成为负担，建议优先迁移聊天归档。账号和资料可分阶段处理。
- 单机可先评估 SQLite。正文存一次，另存各账号的可见关系，用事务提交消息和可见记录，用索引支撑按会话查询。清空或删除本人记录对应变更本人的可见关系。多实例共享数据或实测出现写入竞争时，再评估 PostgreSQL。
- 迁移时保留已有消息 ID、原有可见范围、删除语义和分页导出。按每个账号实际剩余的历史建立可见关系，避免恢复已删除的记录。如果迁移账号，保留既有账号标识和密码校验材料。迁移前准备备份并验证恢复。

## 6. 日常聊天体验

| 建议优先级 | 功能 | 预期体验 |
| --- | --- | --- |
| 已实现 | 逐条显示发送结果 | 消息气泡显示发送中、已确认、发送失败或结果待确认。失败和待确认时可取回正文。安全重试仍需服务端去重语义。 |
| 已实现 | 缩短断线后的恢复路径 | 聊天页提供「重新连接」，带入原服务器与用户名。同址同账号重新认证后恢复原会话和窗口草稿。自动重连待评估。 |
| 高 | 按需加载历史与搜索定位 | 先显示会话摘要和最近一批消息，向上滚动时加载旧记录并保持阅读位置。搜索结果支持跳到原消息和查看上下文，继续按账号授权范围查询。 |
| 中 | 未读定位、静音和桌面提醒 | 在已有未读徽标和阅读位置保留基础上增加「有 N 条新消息」入口，跳至第一条未读。可随群组功能加入按会话静音和可选的桌面提醒。 |
| 中 | 引用回复 | 允许从消息菜单发起回复，发送时显示引用，点击引用定位原消息。适合公共聊天室和多人群组里的并行话题。 |

发送反馈和重连的验证记录见 [当前状态](STATUS.md)。若先邀请他人试用，可优先安排双击启动、最近服务器和局域网发现。若先做公网试用，按第 1 节推进连接保护和容量验证。离线投递、对方已读回执和找回密码仍是待讨论的后续选项。
