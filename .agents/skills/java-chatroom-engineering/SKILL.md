# Java 多人聊天室开发与验证

从用户意图推导规格与评测，再用评测驱动 AI 编码、验证和修订。以目标项目的源码、公开行为和运行证据为依据，沿用其 Java 版本、构建方式与通信约定。

## 从意图到交付

1. **定位现有行为。** 阅读项目约定和交接资料，核对 Git、构建配置、启动入口和测试。沿实际调用链追踪客户端操作 → 协议编解码 → 身份校验 → 路由与存储 → 客户端接收与展示。根据任务定位连接、会话、数据及后台工作的归属。尚无源码时，将实现状态记为待确认，先写最小可运行范围和验收。
2. **表达意图，确定范围。** 写明角色、原始问题、期望结果和本轮边界。新项目把连接、多人广播、隔离的私聊和断开清理作为可独立验收的切片，按用户目标选择 MVP。接续项目根据用户指定的需求选择路线图条目。只确认会改变范围、权限、兼容性、数据结果或验收阈值的歧义。规格、协议和评测齐备时直接推进。
3. **先写规格和评测。** 每条规格写「编号｜角色与前置状态｜触发与输入边界｜预期结果及可见范围｜拒绝或失败后的状态」。用同一编号关联正常、边界、错误或第三方隔离用例。验收以实际收包、重连后的名额、重启后的记录或界面状态为准。规格无法从用户意图推出时，注明待确定的边界。编写正式评测或课程作业时，使用 [评测设计与记录模板](references/evaluation-playbook.md)。
4. **让 AI 按规格实现。** 将意图、规格编号、已有入口和通过条件作为编码输入。按可独立验证的改动实现与补测，优先走用户使用的入口。界面任务沿用业务和网络契约。协议变化时同步两端、协议说明和兼容性用例。跨线程回写前核对连接、账号及会话归属，避免迟到结果覆盖新状态。
5. **验证，按证据修订。** 使用隔离账号、临时数据目录和回环端口执行专项与必要回归。测试失败先核对夹具及观察条件，再判断实现或规格哪个有误。实现偏离规格时修复后重跑。需求有歧义或改变时，按确认后的边界更新规格与评测。记录命令或步骤、版本、环境、预期、实际结果和证据位置，标明 `PASS`、`FAIL`、`NOT RUN` 或 `NOT SUPPORTED`。区分实现状态和验证结果，并将现场验收按环境和版本单独记录。

目标项目为 LTalk 时，按需求在 [LTalk 实现与评测案例](references/ltalk-example.md) 中选取代码入口、可执行用例和历史证据。其他项目用本项目的约束、夹具、命令和阈值。

## 按任务选择检查

| 任务 | 实现检查 | 可执行的验收 |
| --- | --- | --- |
| 路由、社交与历史 | 从服务端确认发送身份、接收范围、回显语义和历史授权。 | 用发送者、合法接收方和第三方验证同一条带唯一标记的消息。加上在线、离线、入群、退群等会改变权限的转换，并检查相关历史读取入口。 |
| TCP 帧与正文编码 | 核对编码、帧边界、限制单位、错误策略和同一连接的串行写入。 | 涉及流解析时拆开包含多字节字符的帧，再合并写入多帧。检查刚好达限、超限、非法帧和半帧 EOF 后的行为。 |
| 连接生命周期与发送结果 | 核对接入、认证、重连的状态和资源归属。分别定义服务端接受、回显、收件人收到的证据。 | 区分主动退出、异常关闭和单向静默。确认超时后检查迟到回显归属、名额复用和新会话状态。重试行为按项目已定义的幂等契约验收。 |
| 并发与公网连接 | 核对自身连接上限、未认证名额、慢端隔离和证书校验。共享锁内避免等待网络 I/O。 | 用同时登录、停止读取、集中重连、突发消息测试。记录在线人数、连接方式、实际负载与时长、端到端延迟口径和断线数。 |
| 数据、历史和附件 | 对照授权模型检查消息与可见状态的事务、失败清理、旧数据和备份回退。 | 用隔离数据验证存储失败、确认或取消、重启和升级。对照投递、搜索、导出、引用及下载的可见范围。 |
| Swing 界面与交互 | 网络操作在后台执行，组件和会话展示状态在 EDT 更新。保留正常入口和键盘路径。 | 从可见控件复现。检查连续操作时的滚动定位、草稿与焦点、宽窄窗口及相关主题。系统对话框、剪贴板和高 DPI 按实际桌面环境记录。 |

用有限超时等待业务事件或状态。验证第三方隔离时先确认其已就绪，同轮保留一条能被它正常接收的消息作对照。

## 高风险代码的人审

涉及不兼容协议、认证授权语义变更、不可逆数据操作、线上公网暴露或发布等高风险动作时，向人工审阅者说明具体影响、失败后果、隔离验证和回退方案。核对已给出的授权范围，在尚未获授权的动作前获得批准。等待期间继续代码阅读、评测设计和已获授权的隔离验证。
