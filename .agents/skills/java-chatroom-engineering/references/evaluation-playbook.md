# 评测设计与记录模板

用于课程规格编写、多端交互、跨版本变更和现场验收。小型修复可在现有任务说明中保留所需字段。可复用已有测试和夹具，由本次用户意图决定通过条件。

## 从意图写到评测

1. 把用户原话改写为可观察的目标，注明适用角色、会话类型、连接和数据状态。把本轮交付和后续待办分别列出。先找已确认的约束，再从源码和测试核对现状。
2. 拆解容易混淆的语义。例如发送反馈要定义哪一端接受才算成功、何时进入结果待确认、迟到的响应如何处理。群历史要定义何时获得授权、退群后保留哪些记录、哪些查询复用此权限。
3. 每个用例只承担清楚的结论。第三方隔离需要一名正常接收者和一名无权者，同轮验证无权者能正常收到一条对照消息。分页覆盖刚好满页、跨页和目标尚未加载。状态竞态通过可控回调、假时钟或阻塞点复现，并在有限时间内等业务事件。
4. 性能规格写明同时在线、登录或重连波次、收发频率、运行时长、数据规模与容许的错误数。明确延迟从何时开始、何时结束，例如从发送到最后一名预期客户端收到。阈值以项目指定值为准，测试夹具放宽的连接或限流参数随结果记录。

遇到实现方案有取舍时，写明哪条规格促成选择，以及用什么证据验证。登录历史逐条出现时，可分别测初始查询、传输和 EDT 更新，再决定优化初始加载还是改存储。变更存储前，明确是新目录初始化、兼容原库，还是迁移已有数据。需要迁移时，用旧版本夹具验证首次升级、再次启动、失败回滚与备份恢复。

### 可复制模板

```markdown
## 规格 <需求编号> <用户目标>

- 意图与本轮范围
- 角色、前置状态与可复用入口
- 触发、输入范围与边界值
- 可观察的结果、接收者及历史可见范围
- 拒绝、取消或失败后的状态与资源
- 兼容约束与待确认的业务边界

| 用例 | 前置和输入 | 步骤 | 期望结果与检查点 | 执行方式 |
| --- | --- | --- | --- | --- |
| <需求编号>-01 | <夹具> | <正常操作> | <正向结果> | <测试方法或人工步骤> |
| <需求编号>-02 | <边界状态> | <边界操作> | <边界结果> | <测试方法或人工步骤> |
| <需求编号>-03 | <无权角色或故障> | <拒绝/中断操作> | <隔离、提示及清理> | <测试方法或人工步骤> |
```

### 示例 · 私聊只向授权收件人交付

规格 `MSG-01`。有权限的 A 向在线 B 发送一条合法私聊。B 收到一次正确的发送者与正文，A 按项目契约收到回显或确认，在线 C 收不到该私聊。如果 B 处理中离线，按项目契约验证拒绝或离线交付。若项目归档，再验证 C 从搜索、历史或导出也无法取得该消息。

| 用例 | 前置和输入 | 操作与通过条件 |
| --- | --- | --- |
| MSG-01-01 | A、B、C 登录就绪，A 获得向 B 发送的权限 | A 发一条当前用例独有正文，B 核对身份、正文和数量。A 发一条公共对照消息，C 收到对照消息。在有界观察时间内 C 始终未收到私聊。 |
| MSG-01-02 | 复用上述三人，故障前核对 B 在线 | 关闭 B 后等服务端公布离线，再发送带新标记的私聊。按已有契约检查离线交付结果或明确拒绝，并核对 C 的收包。 |
| MSG-01-03 | 项目归档该类消息，已知 MSG-01-01 的消息标识 | C 尝试经适用的历史读取入口查询。期望为权限拒绝或无该正文，按实际接口约定断言。重新登录 B 后，以正向查询确认夹具仍能读到该消息。 |

## 选择现场证据

| 环境 | 可得到的证据 |
| --- | --- |
| 单元与本机回环 | 帧解析、路由、事务、超时、取消和并发边界。可自动注入单向静默、慢读端或写入失败。 |
| Swing 离屏与真实窗口 | 离屏测试覆盖 EDT 组件动作、尺寸、布局及渲染。真实窗口补测原生选择器、系统剪贴板、焦点和高 DPI。 |
| 局域网、宿主机加虚拟机 | 记录服务端位置、客户端数量、实际拓扑和静默断开的模拟方式。发现测试记录网卡和广播是否到达客户端。 |
| 云端试用与压测 | 记录服务端与客户端版本、数据版本、连接方式、终端数量、已操作的功能和日志时间窗。短流程试用和持续并发测量各自保留结果。 |

## 验证与修订记录

执行记录可用一行表示为「用例｜代码或 JAR 版本｜环境与夹具｜命令或步骤｜实测｜状态｜证据与执行者」。人工反馈记录实际使用的设备和已反馈的项目。版本、设备数或逐项结果未知时标明未知。自动化只在断言满足时记 `PASS`。已运行并偏离规格记 `FAIL`，环境缺失或尚未运行记 `NOT RUN`，项目缺少相关能力时记 `NOT SUPPORTED` 并注明与本轮范围的关系。课程报告可选一条完整链路展示用户意图、规格编号、AI 实现位置、评测步骤与实测结果。

定位失败时，先验证夹具真的到达了前置状态和分支。修正夹具后按原条件重测。若实现偏离规格，保留复现条件并增加回归。若实测暴露规格歧义，记录原规格、有待确认的边界、确认后的规格和重测结果。需要人工批准时记录获批动作与限定范围。
